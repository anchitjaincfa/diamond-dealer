# Security policy

## Supported versions

Security fixes apply to the latest deployment and default branch.

## Reporting

Use GitHub private vulnerability reporting. Include the affected page, endpoint, or commit; synthetic reproduction steps; observed impact; and a minimal proof of concept when appropriate.

Do not post secrets, tokens, personal data, or active exploit details in a public issue. Allow a reasonable response window before disclosure.

## Demo data rules

Use synthetic data only. Never submit or commit payment credentials, government identifiers, home addresses, private customer correspondence, real transaction documents, access tokens, or signing keys.

If personal or confidential data is discovered, stop processing it, restrict access, rotate exposed credentials when relevant, and notify the owner privately.

Contributions should preserve secret scanning, least-privilege environment variables, security headers, input validation, upload restrictions, lifecycle audit logs, and separation between fixtures and future production storage.
